# AICM-NT4K DV 监控上位机 需求说明书

> 版本：v1.0（2026-10-14） | 对应代码现状：dev 分支 v1.8.1（f417c32）
> 配套文档：[SPEC.md](../SPEC.md)（实现规格）、[README.md](../README.md)（使用手册）、[decisions.md](decisions.md)（决策台账）

## 1. 引言

### 1.1 目的
博雷顿控制器 Ares AICM-NT4K 在设计验证（DV）阶段需要长时间的 CAN 总线信号监视、故障观测与测试结果留存。本上位机替换人工示波器/总线分析仪方式，提供**实时解码、状态判定、曲线记录、测试模式下发、结果上报 MES** 的一体化工位工具。

### 1.2 范围
- **在本项目内**：CAN 总线监控 UI、DBC 解码与状态判定、三套硬件适配器、限值交叉校验、MES 04 测试结果上传、数据存储与导出、打包发布、离线仿真。
- **不在本项目内**：CAN 总线报文协议本身的制定（由固件 DV_CAN.c / DBC 定义）、MES 系统内部逻辑、固件缺陷修复（另有记录，见 8.3）。

### 1.3 术语
| 术语 | 含义 |
|---|---|
| DV | Design Verification，设计验证 |
| CDD | CAN 硬件适配器（周立功 USBCANFD-200U / 智嵌 ZQWL / PEAK PCAN-USB） |
| 交叉校验 | 上位机按限值表复核电压数值并与 MCU 状态位比对 |
| 04 | MES 测试结果上传命令码（`04;...`） |
| SN | 产品序号（扫码枪输入） |

### 1.4 读者
测试工程师（日常使用）、工艺/质量（判定规则 MES 上报口径）、维护开发（扩展限值/检测项）。

## 2. 使用场景

**S1 实台监控**：连接 CAN 适配器 → 启动实时监控 → 总览/相机/IO 面板观察各信号状态，异常自动标红。

**S2 故障注入验证**：测试员触发_fault（如令断 HSD、拔电压）→ 上位机实时反映状态变化并记录。

**S3 测试结果上报**：测试员扫 SN → 点「上传MES(04)」→ 上位机采集全部有效通道 → 按限值/状态判定 → 拆条上报 → 界面回显三态结论（MES接收 / MES拒绝 / 网络失败）。

**S4 离线演示/开发**：无硬件环境用内置仿真器（数据源=仿真）跑通全部功能。

## 3. 功能需求

### FR-01 CAN 通讯与硬件适配（P0）
- 需求：支持三类适配器接入，均走 500 kbit/s，UI 下拉框选择；**自动探测**（官方 ZLG 库静默尝试 → ZQWL 库回退）与**手动指定**并存；PCAN 以 `PCAN:PCAN_USBBUS1~8` 前缀路由，不支持自动探测。
- 验收：真机 ZLG 200U 自发自收/收发一致；同机内 ZLG 官方库与 ZQWL CDC 库可共存不冲突；PCAN 待硬件实测（依赖 `PCANBasic.dll`，用户自备）。

### FR-02 报文解码与通道建模（P0）
- 需求：按 DBC 解析全部报文（当前 18 帧）；报文 100 ms 周期，超时（周期×3）判"超时"并在报文面板高亮；数值通道由 `config/signals.json` 定义（desc/msg/整数位信号/小数位信号/frac_div/单位/status_sig），当前 **42 个数值通道**（20 路电压 + 9 路温度 + 6 路 CPU 负载 + 7 路 HSD）；非数值通道（I2C/SPI/SSD/Camera/串口等）按 MCU 上报状态位展示。
- 验收：BC（新 DBC）更新后无需改代码，仅更新 DBC+signals.json；超高优先级帧解码值与固件 Generate_ADC_CANMsg 对齐。

### FR-03 状态判定与限值交叉校验（P0）
- 需求：纯状态类通道按 `status.<信号>.normal` 值比对（绿/红）；带限值通道由 `config/limits.json`（**29 路**=15 固件电压窗口+14 工艺，含 9 路温度 **0~85℃**、AD1/AD2/IGN/TBOX_WP <1V、CAN0_INH 17~21V）做交叉校验，四态：
  | MCU 位 | 数值 | UI | MES 结论 |
  |---|---|---|---|
  | 正常 | 窗口内 | 绿 | PASS |
  | 异常 | 窗口外 | 红 | NG |
  | 正常 | 窗口外 | 红 | **强制 NG**（不信位） |
  | 异常 | 窗口内 | 黄 | PASS |
  | 无状态位 | 窗口内 | 绿 | PASS |
  | 无状态位 | 窗口外 | 红 | NG |
  温度 9 路无 MCU 状态信号，按纯窗口判定；无窗口通道回退 MCU 位。
- 限值表**必须**由 `tools/gen_limits.py` 从固件 DV_CAN.c 自动生成，防两份限值漂移；`limits.json` 为三层结构 `{_source,_generator,limits:{...}}`。
- 验收：电压卡四态验证；温度卡按窗口判绿/红；用户可在总览 tooltip 看到判定依据。

### FR-03b 自动判定（P0）
- 需求：新增「判定」页签，每 1 秒自动汇总全部检查项，无需手动点击。**所有功能 PASS 才显示绿框 PASS，任意一项 Fail 都显示红框 FAIL**；在收到 SOC 发出报文（首帧）后才开始判定，未收到时显示灰框“等待数据”，不会直接报红。
- 范围：`limits.json` 全部 29 路限值（黄灯按合格）+ `signals.json` 全部健康状态位（未收到算 Fail）+ DUT 上报的 16 条报文（超时/未收到算 Fail）。
- 以太网范围：当前只判 `eth0_1`/`eth0_7`/`eth0_8`/`eth1_1` 四路；`eth0_2~eth0_6`、`eth0_9` 暂未实现，标 `verdict_skip`，IO 面板仍显示但不参与判定。
- 排除：0x680 回读的 10 个测试开关、固件未赋值的 5 个电压状态位、CAN1~4TEST 外部测试帧、Vector 占位报文。
- 未接负载例外（当前 P230/P234，即 U1000/U1001 的 CH0）：开路状态放行；U1000/U1001 的开路 6/错误 8 仅由对应未接通道开路解释时放行，过载/短路仍 Fail。接负载后删除 `signals.json` 中对应 `unconnected` 标记。
- 结果展示：标题区显示 PASS/FAIL、总数/失败数和判定时间；下方按类别展开明细，失败组自动展开。判定后收到新帧提示“结果为判定时快照”。
- 验收：仿真正常窗口 PASS（140 项）；注入 IGN/Cam3/LSD/HSD 故障后 FAIL 且能定位到具体项；恢复后重新判定 PASS。

| 面板 | 需求 | 优先级 |
|---|---|---|
| 总览 | 20 路电压卡（限值三色）+ 板温 9 卡 + CPU0-5 负载 + 异常通道计数 + 报文健康指示 | P0 |
| 判定 | 一键汇总全部检查项，全 PASS 绿框 / 任意 FAIL 红框；分组明细可展开 | P0 |
| 相机 | Cam0-10 Linklock/Videolock/Crc 矩阵、FPS、json 报文缺失表 | P1 |
| IO 状态 | HSD U1000/U1001 自检+HSD1-7 ADC+P23 端口诊断、LSD、RS232/RS485/SPI/SSD/CAN/I2C 状态与错误计数 | P0 |
| 曲线 | 电压/温度/CPU 负载实时曲线，**8000 点自适应抽稀**、HH:MM:SS 相对时间轴，可长时间过夜记录 | P1 |
| 报文 | 帧日志 6 列（含 Bin 列）、超时高亮、单元格 Ctrl+C 复制 | P1 |
| 发送 | 原始帧/按DBC报文两种方式 + 周期发送 | P1 |
| 启动测试 | 点击「启动测试」开始接收并自动进入测试模式（1s 周期下发 0x680 DVtest_Switch，DV 开关+HSD 使能）；停止时下发全 0 复位 | P0 |
| 数据导出 | SQLite 落库 + 按时间范围 CSV 导出（frames+signals两表） | P0 |

### FR-05 数值精度与展示一致性（P0）【用户原话强调】
- 需求：**报文读到的是对的** —— 上位机解码值与真实 CAN 原始帧严格一致，总览卡片数值必须与"报文面板看到"的原始值一致；电压 2 位小数、温度/负载按原始精度；不发买卖建议类误读。
- 验收：仿真+真机均对同一数值通道做 UI 卡片 vs 报文面板 bit 级对齐审查。

### FR-06 测试结果上传 MES 04（P0）
- 需求：
  1. UI 提供 SN 输入框（扫码枪=键盘输入，回车即触发）、「上传MES(04)」按钮、状态栏回显。
  2. 检测项 = 白名单数值项（`config/mes.json.channels`，当前 26 项，上传原始数值）+ 其余自动判定项（PASS=1 / FAIL=0，含状态位、报文接收等），整机结论与「判定」页一致；无 SN/无检测项/未启用均需给明确提示。
  3. 04 报文（9 段，段 1-7 固定结构）：`04;DQ2206ZSC0160;{SN};TEST-海思拓手动测试工序;;;;测试开始时间;项1:值1,项2:值2`
     - **段 1-7 固定结构**：工单号 `DQ2206ZSC0160`、序号（=SN 号）、工序名称 `TEST-海思拓手动测试工序`，其余三槽为空；
     - **段 8**：测试开始时间 `yyyyMMddHHmmss`；**段 9**：检测项 `名称:数值`，半角冒号/逗号；
     - **每条最多 7 项**，超限自动拆成多条 04；序号即 SN 号，原样透传。
  4. 05 过站报文（OK/NG 都发送）：`05;DQ2206ZSC0160;{SN};TEST-海思拓手动测试工序;;;;测试开始时间;OK`
     - **段 1-8 与 04 字面完全相同**（工单号固定 DQ2206ZSC0160，序号为 SN），仅命令码为 `05`；
     - 判定 NG 时追加段 10：`05;...;测试开始时间;NG;NG项1:值1,NG项2:值2`（只带上位机判为 NG 的检测项）。
  5. 对外样例 JSON 的 `items` 为 `"名称:数值"` 字符串数组，顶层带 `verdict`（OK/NG），不输出上下限与逐项判定。
  6. 传输层：stdlib urllib（不引 requests），form POST（`application/x-www-form-urlencoded`）或 GET；HTTPS 自签证书 `verify_tls=false`；URL/工位字段/超时全部配置化（`config/mes.json`）；`enabled=false` 时按钮禁用。
  7. 编排：先发 04（全部拆条），再发 05；某条 `NG;理由;` → **停止后续条**；网络异常 → 指数退避 2^n（默认 3 次）后**整组重发**（允许 MES 侧重复）。上传全程在**后台线程**执行（超时/退避不得阻塞界面），上传中按钮禁用、状态栏显示「MES 上传中…」，结束后恢复按钮并回填结论。
  8. 结果三态：`MES 接收 N/N 条`（绿） / `MES 业务拒绝·原因`（红） / `MES 上报失败·网络原因`（黄）。
  9. 每次上传前把本次内容落盘到 `data/mes_last_upload.json` 与 `data/mes_last_upload.txt`（后者为拆条后的 04/05 命令），断网也能核对实际发出内容；上传过程中另把**每条请求与响应原文**追加到 `data/mes_send.log`（`BEGIN`/`SEND`/`RESP`/`FAIL`），连真实 MES 时也可事后追溯；离线验证可用 `python tools/mes_mock_server.py`（本地 MES 桩，浏览器直接打开该地址会显示最近收到的 04 与累计条数，并写 `data/mes_received_*.log`）。地址切换用 `python tools/mes_url_switch.py --local|--factory`，同时改源码与发布包内配置。若既要上传真实 MES 又要本机留证，可启动 `python tools/mes_relay_server.py --upstream <真实MES地址>`（默认监听 8091），把 `url` 指到中转桩，报文会先落盘再原样转发并回传 MES 响应（`data/mes_relay_*.log`）。
- 验收：`tests/mes_ui_check.py` 本地桩服务器实测拆条/解析/NG分支/白名单/落盘；`mes_demo.py` 演示组包与编排策略；`tools/mes_mock_server.py` 可离线接收并回显真实上传内容。

### FR-07 离线仿真与开发自验证（P0）
- 需求：内置 DVTestSimulator 按 DBC 时序无硬件跑通全功能（可视化渲染截图 `tests/render_ui.py`、冒烟 `tests/smoke_ui.py`、MES 树桩 `tests/mes_ui_check.py`）；无头 GLM 环境可跑；真机可用 `tools/can_self_test.py --device` 单测适配器；改代码先跑冒烟再提交。
- 验收：smoke PASS（frames≈448、故障注入 HSD3/IGN 正常反映、恢复 OK）、mes_ui_check PASS（拆条数=ceil(n/7)）。

### FR-08 发布打包（P0）
- 需求：PyInstaller onedir 打 Windows 包；**DLL 清单固化**：`zlgcan.dll`（官方 WinUSB x64）+ `zlgcan_zqwl.dll`（ZQWL CDC 专用）+ `PCANBasic.dll` + `kerneldlls/` + `msvcr120/msvcp120.dll` + `MSVCP140/VCRUNTIME140*`；未列入打包清单的 `*.mat/.csv/*shots*` 均排除。
- 验收：拔包后双击 main.exe 起一个干净环境直接连接真机；交付轮次用 tag 标版本（如 v1.8.1），commit 格式 `type: 中文描述`。

### FR-09 硬件 IO 采集增益类监控
- 需求：HSD 状态（U1000/U1001 自检码 0-255、ADC 0-255）、LSD 错误计数等按 MCU 上报宽度原样解码，不做二次推理。
- 验收：与固件 DV_IO 相关 Code 表对齐。

## 4. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-01 | 实时：UI 刷新 ≥ 10 Hz；100 ms 周期报文不丢帧（长时运行 8000 点抽稀内存有界） |
| NFR-02 | 环境：Python 3.12.7 + PyQt5 + pyqtgraph + numpy；不引重包（requests/pandas/matplotlib）；Windows 主，WSL 仅做无头测试 |
| NFR-03 | 可维护：全部判定阈值/通道配置都进 `config/*.json`，改配置不改代码；决策进 `docs/decisions.md` |
| NFR-04 | 安全：MES 走工位内网，不上传公网；无任何熊 key/明文密码；验证命令可重复执行（冒烟用例随仓库提交） |
| NFR-05 | 并发：CAN 接收线程 + UI 主线程分离，收发互不阻塞 |

## 5. 外部接口

### 5.1 CAN 侧（读固件）
- 周期 100 ms；MCU 发出报文含 `0x655 MCUTempData`（20 个 *_Status bit）、电压采样帧、温度帧、HSD/IO/Camera 帧等 18 帧。
- 上位机只读（除 `0x680 DVtest_Switch` 测试模式主动下发）。

### 5.2 MES 侧（写 MES）
- HTTP POST `http://192.168.20.100:8090/WebService/MesATEApi.asmx/ATECommandCode`，参数 `commandString`（地址配置在 `config/mes.json`）；
- 响应 `<ATECommandCodeResult>OK;/NG;原因;</ATECommandCodeResult>` 或 `<string xmlns="http://mesateapi.com/">` 或裸串，均须能解析；
- 失败重试不阻塞 UI（后台线程 + 状态栏回显）。

### 5.3 硬件外设
- USB 扫码枪（键盘模拟）输入 SN；
- 同一台工作站可同时插 ZLG / ZQWL / PCAN 三类适配器。

## 6. 现状边界与已知风险

1. **5 路电压无状态位**（AD1/AD2/IGN/CAN0_INH/TBOX_WP）固件从未赋值。上位机已改为**只按窗口判定、忽略状态位**（2026-11）：AD1/AD2/IGN/TBOX_WP <1V 合格，CAN0_INH 17~21V 合格；固件缺陷本身仍**暂不修**，待批量验证后统一改。
2. 固件欠压判定的 `UVRecoverHyster/UVRecoverDebounce` 笔误（VBATT_SOC_P 的 UVConfirm=15.3 实际按 17.0 判）→ 待固件版本更新后重新生成 limits.json。
3. MES **失败重传按钮、01 检查命令、SOAP 1.1/1.2** 尚未实现；过站 05（OK/NG 都发，NG 带 NG 项）已实现。
4. `PCANBasic.dll` 已入库但未做真机验证（等 PEAK 硬件）。
5. MES 04 与固件限值拉通依赖 `tools/gen_limits.py`：固件窗口改动必须重新生成否则漂移。
